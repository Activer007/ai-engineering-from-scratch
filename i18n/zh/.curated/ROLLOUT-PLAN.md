## v1.2历史复核结论

16 课跨领域、按风险抽样的安排适合验证方法：实际暴露了矩阵指代、可训练参数、token、百分比和 GFM 乘号问题。它不是常规教学批次，也不能用来估计其余 507 课的缺陷率。

本次重新读取 fork PR #1–#6：均为 open draft、未合并，head 与试点完成时一致；未发现后续改写。将 #2–#6 的新译文件只读组合到隔离工作树后，重新通过 **33 项控制回归、16/16 严格记录检查与两次字节一致重放**。这没有合并任何远端 PR。此前的 16 课 GFM 桌面检查记录仍有效，因为目标内容未变；本次不把历史检查说成重新逐页执行。

v1.1 中“内部生产批 5–15 课”和“PR 3–5 课”容易形成过大的待审队列；试点评估中“先关闭源文和网站门槛再继续”又把不同发布面的限制混为一个总阻塞。本版改为以下规则：

- 常规批以同主题、相邻依赖的 **3–5 课**为起点，默认 4 课；不足 3 课但逻辑完整时可以独立成批
- 不用课数代替负荷：统计除围栏、展示公式、行内代码外的英文词数，同时看表格、跨文件依赖和风险
- 初始建议每批不超过约 4,000 个可译英文词；单课超过约 1,500 词或包含复杂维度推导、协议安全、训练/量化断言时，优先 1–2 课专批；这是保守调度阈值，不是测得的审校产能
- 同时在制最多一个交付批；可把它拆成两条翻译线，但未审稿不滚入下一批；每课必须有作者以外的完整技术对照和中文通读
- 前置课程已有英文即可继续新译；前置中文是否合并是读者可用性/发布问题，不是起草许可
- 源文缺陷与网站适配单列处理：不擅自改英文技术含义，不阻塞无关草稿；受影响课程仍不得宣称可执行指导或发布验收通过

## v1.2历史每课 / 每批完成标准

### 已审草稿门槛

1. 固定 source commit、Git blob、SHA-256、目标 SHA-256 与逐段块记录；没有旧中文、旧缓存、旧 PR 文本或英文 fallback 混入
2. 全文 EN→ZH 技术审查及独立完整中文通读；列出并修复翻译缺陷，S0/S1/S2 不遗留；数值、否定、因果和指代逐项检查
3. 代码载荷、标识符、路径、URL、API/classes/flags、公式、数值、表格列数、标题层级与源块映射通过严格检查；只对裸围栏补 `text`、对必要 GFM 标点做最小格式修复并记录
4. 与冻结术语一致；多义词注明当前语境；新增词以本阶段附表记录，不能覆盖试点冻结词表
5. 双目录重放一致、对已有不同输出拒绝覆盖；本地课程/认证/README 基线审计与 diff 检查通过
6. 逐课实际 GitHub GFM 桌面页检查，核对标题锚点、表格、代码、Mermaid/figure 表现；未检查的移动端不能写“通过”
7. 安全离线示例按条件运行；安装器、云资源、凭据、付费 API、真实推送/删除操作不运行。没有对应测试、缺依赖和未执行分别记录
8. 每课独立 Conventional commit（标题≤72字符），工具/计划/术语支持提交分开；远端比对字节并重新查 draft/base/head/checks

### 保持独立的发布门槛

- 原站中文锚点/章节样式/来源路由适配与真实网站浏览器验收仍 **未通过**；GFM 不代表网站交互图、导航、复制或移动端验收
- fork Actions 保持禁用；0 checks 表示未运行，不表示 CI 通过
- 固定英文中的错误/过时声明须单独修订并同步中文；忠实翻译不等于事实背书
- 用户尚未批准合并、部署或发布；所有本批结果保持 draft
