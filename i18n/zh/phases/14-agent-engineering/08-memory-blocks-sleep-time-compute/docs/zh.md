# 记忆块与休眠时计算

> 将记忆按功能划分为独立的记忆块（memory block），让模型能够直接编辑；再由休眠时智能体（sleep-time agent）在主智能体（primary agent）空闲时异步（asynchronously）整合（consolidation）记忆。智能体（agent）借助这两个思路，让记忆的范围超越单次对话。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** 阶段 14 · 07（MemGPT）
**Time:** ~75 分钟

## 学习目标

- 列出 Letta 使用的三个记忆层级：核心记忆（core）、回忆记忆（recall）和归档记忆（archival），并说明各自的作用。
- 解释记忆块模式：用户信息块（Human block）、角色设定块（Persona block）以及用户自定义的块，都是具有类型的一等对象（first-class typed objects）。
- 说明什么是休眠时计算（sleep-time compute）、为什么它不在关键路径（critical path）上，以及为什么它能采用比主智能体更强的模型。
- 实现一个由脚本驱动的双智能体循环：主智能体负责响应，休眠时智能体在轮次之间整合记忆块。

## 要解决的问题

MemGPT（第 07 课）解决了虚拟内存（virtual memory）的控制流问题。在生产环境中，随之出现了三个问题：

1. **延迟。** 每次记忆操作都处在关键路径上。如果智能体要在用户等待时裁剪、生成摘要或协调不一致的信息，尾延迟（tail latency）就会大幅攀升。
2. **记忆陈化（memory rot）。** 写入不断累积，与新信息相矛盾的事实仍然留存。检索结果被过时内容淹没。
3. **结构丢失。** 扁平的归档存储无法表达这样的关系：“用户信息块始终在提示词（prompt）中；角色设定块始终在提示词中；任务块（Task block）则按会话切换。”

Letta（letta.com）是原 MemGPT 项目在 2024 年采用的平台名称，论文提出的模式仍沿用 MemGPT 这一名称；2026 年的 Letta V1 重写则是之后另一个独立的步骤。记忆块让结构变得明确，休眠时计算则将整合工作移出关键路径。

## 核心概念

### 三个层级

| 层级 | 范围 | 存放位置 | 写入方 |
|------|-------|----------------|------------|
| 核心记忆 | 始终可见 | 主提示词内部 | 智能体的工具调用（tool call）+ 休眠时重写 |
| 回忆记忆 | 对话历史 | 可检索 | 自动记录每个轮次 |
| 归档记忆 | 任意事实 | 向量 + KV（键值）+ 图 | 智能体的工具调用 + 休眠时摄入 |

核心记忆就是 MemGPT 中的核心记忆。回忆记忆是对话缓冲区连同其中已被逐出的尾部内容。归档记忆是外部存储。这种划分解决了 MemGPT 两层结构中职责混杂的问题。

### 记忆块

记忆块是核心层中具有类型、经过持久化（persistent）保存且可编辑的分区。最初的 MemGPT 论文定义了两种：

- **用户信息块**：关于用户的事实，如姓名、角色、偏好和目标。
- **角色设定块**：智能体的自我认知，如身份、语气和约束。

Letta 将其推广到任意用户自定义的块：用 `Task` 任务块保存当前目标，用 `Project` 项目块保存代码库相关事实，用 `Safety` 安全约束块保存硬性约束。每个块都有 `id`、`label`、`value`、`limit`（字符数上限，character cap）和 `description`（让模型知道何时该编辑它）。

可以通过工具接口编辑这些块：

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)`：精简一个接近上限的块。

### 休眠时计算

这是 Letta 在 2025 年新增的机制：在后台运行另一个智能体，让它处在关键路径之外。休眠时智能体处理对话记录和代码库上下文，将 `learned_context`（习得上下文，learned context）写入共享块，并整合归档记录或对其进行失效处理（invalidation）。

由此带来以下特点：

- **不增加延迟。** 主智能体的响应无需等待记忆操作。
- **可以采用更强的模型。** 休眠时智能体可以使用更昂贵、更慢的模型，因为它不受延迟约束。
- **自然形成的整合时段。** 趁用户没有等待时，去重（deduplication）、生成摘要，并将与新信息相矛盾的事实标记为失效。

这种模式与人的工作方式相似：先完成任务，再睡上一觉，让长期记忆在夜间逐渐沉淀。

### 原生推理

Letta V1（`letta_v1_agent`，2026）弃用了 `send_message`/心跳机制（heartbeat）和行内的 `Thought:` token（词元），转而采用原生推理（native reasoning）。OpenAI 的 Responses API（API 指应用程序编程接口）与 Anthropic 支持扩展思考（extended thinking）的 Messages API 会通过单独的通道输出推理，并在轮次之间传递（生产环境中跨提供商传递时采用加密形式）。控制循环仍然是 ReAct（推理与行动）。思考轨迹（thought trace）由结构来表达，不再依靠提示词中的格式。

### 这种模式容易在哪些地方出问题

- **记忆块膨胀（block bloat）。** 不停地调用 `block_append` 很快就会触及上限。在那次会导致超限的写入之前，接入记忆块摘要生成器。
- **静默漂移（silent drift）。** 休眠时智能体重写了一个块，主智能体却始终没有察觉。对记忆块进行版本管理，并在轨迹中展示差异（diff）。
- **整合过程投毒（poisoned consolidation）。** 休眠时智能体把攻击者能够触及的内容处理后写入核心记忆。第 27 课的内容同样适用于休眠时的这一攻击面。

## 动手实现

`code/main.py` 实现了：

- `Block`：id、label、value、limit、description。
- `BlockStore`：CRUD（创建、读取、更新、删除）以及 `near_limit(label)` 辅助方法。
- 两个由脚本驱动的智能体：`PrimaryAgent` 处理一个轮次，`SleepTimeAgent` 在轮次之间整合记忆。
- 一条展示三轮对话的轨迹，其中包含记忆块写入；随后的一轮休眠时处理会为一个块生成摘要，并将一条过时事实标记为失效。

运行方式：

```text
python3 code/main.py
```

对话记录展示了这种分工：主智能体的轮次响应迅速，并写入原始信息；休眠时的一轮处理则负责压缩整理（compaction）和清理。

## 实际使用

- **Letta**（letta.com）提供参考实现，可自行托管，也可使用托管云服务。
- **Claude Agent SDK skills** 可以作为以记忆块形式组织的知识来使用。SDK 指软件开发工具包；这里的技能（skill）是一个有名称和版本、可检索的指令块，由智能体按需加载。
- **自行构建**适合希望掌控存储后端的团队。采用 Letta API 的接口约定，以便日后迁移。

## 练习

1. 添加一个 `block_summarize` 工具，在 `near_limit` 返回 true 时，用模型生成的摘要替换块的值。哪个触发阈值能同时尽量减少摘要调用和记忆块溢出？
2. 实现休眠时对归档记忆的去重：如果两条记录的文本中 token 重叠比例 >90%，就将它们合并为一条。只在休眠时的那轮处理中执行，绝不放到关键路径上。
3. 对记忆块进行版本管理。每次写入都记录旧值和差异。提供 `block_history(label)`，让运维人员能排查“智能体为什么忘记了 X”。
4. 将休眠时智能体视为不可信写入方（untrusted writer）。当它们修改角色设定块或安全约束块时，必须先由另一个智能体审查，才能提交。
5. 将示例移植为使用 Letta API（`letta_v1_agent`）。记忆块的 schema（结构定义）会发生什么变化？原生推理又会如何改变轨迹的结构？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------------|------------------------|
| 记忆块 | “可编辑的提示词分区” | 核心记忆中具有类型、经过持久化保存、可由大语言模型（LLM）编辑的片段 |
| 用户信息块 | “用户记忆” | 固定保留在核心记忆中的用户事实 |
| 角色设定块 | “智能体身份” | 固定保留在核心记忆中的自我认知、语气和约束 |
| 休眠时计算 | “异步记忆工作” | 另一个智能体在关键路径之外进行整合 |
| 核心记忆 / 回忆记忆 / 归档记忆 | “层级” | 三层记忆划分：始终可见 / 对话 / 外部 |
| 记忆块上限 | “容量上限” | 每个块的字符数限制，会迫使系统生成摘要 |
| 原生推理 | “思考通道” | 提供商层面的推理输出，而非提示词层面的 `Thought:` |
| 习得上下文 | “休眠时的输出” | 休眠时智能体写入共享块的事实 |
